# Spec: MCP tools

Source: PLAN.md §6.2–§6.8. This is the contract the server implements and the tests check.

## Endpoint and identity

- Streamable HTTP at exactly `POST /mcp`, stateless: a new MCP server and transport per request. `GET` and `DELETE` on `/mcp` return 405.
- Every request carries:
  - `Authorization: Bearer <agent token>` (required; a wrong or old token gets HTTP 401);
  - `X-Pair-Agent: claude-code | codex | <other>` (optional, default `other`);
  - `X-Pair-Project: <project>` (optional when the call carries a registered session id, see below).
- The `Host` header's host name must be allowed (port ignored): `localhost`, `127.0.0.1`, the host of `PAIR41_PUBLIC_URL`, and any in `PAIR41_ALLOWED_HOSTS`. Otherwise HTTP 403. `/live` and `/ready` are not checked.

## Which session is calling

Every tool accepts an optional `_session` string. The `pre-tool-use` hook fills it with the agent's own session id. The server resolves the calling session like this, and never guesses:

1. `_session` given: the session of this person with that agent session id. If none exists yet and the project is known, it is created. If the project header names a different project than the session's, the call is refused.
2. No `_session` (an agent without the Pair41 hooks): the open sessions of this person for this agent kind (`X-Pair-Agent`), in this project when one is given. With none, a new session is created (with no project if none is given).
   - none: a new session is created (agents without hooks);
   - one: that session;
   - two or more: refused with `two sessions are open for <project>; Pair41 cannot tell which one you are. Install the Pair41 hooks (the Pair41 plugin in Claude Code, or pair41 install), which tell Pair41 the session, or close the other session.`

A session is open when it is not closed and has been seen (hook or tool call) in the last 60 minutes.

## Output format

- Content block 1: JSON text (the result). Content block 2, only when there is news: the unread footer, e.g. `pair: 1 unread from sam (question) · call check_messages`. The footer only appears when something arrived since the last notice to this session.
- Partner-written text (messages, board bodies, feed lines) is sanitised (see protocol.md) before it is returned.
- Errors: `isError: true` with a one-line text explaining what to do.
- Ids are strings with a prefix: `m_12` (message), `p_3` (pair), `s_7` (session).

## Pairing is between people

1. **Ask.** A person asks a teammate to pair on a feature: on the teammate's page, or by telling their agent (`request_pair`). There are no solo pairs: Pair41 connects two developers, and one person splitting work between their own agents is better served by one agent with subagents.
2. **Agree.** The teammate accepts or declines: on the Pair41 page, or by telling their agent (`respond_to_pair`). Until both people have agreed, nothing is paired.
3. **Join with the pair code.** Every pair has a short code, such as `amber-otter-42`, shown to both people on the pair page. Each person tells their own agent "join Pair41 pair amber-otter-42" and the agent calls `join_pair` with it. This works for any agent that speaks MCP (Claude Code, Codex, Cursor, ...), with or without the Pair41 hooks. The code only puts an agent of yours on your own side (the server knows whose token is calling), so someone else who learns it cannot join. The person who asked can join their agent at once; the person asked, once they have accepted. An agent that asked or accepted through its own tools is joined at that moment, because its person told it to. Joining another agent with the same code replaces the one on your side; messages still waiting for the old one go to the new one.
4. **Connected.** When both sides have an agent, the agents can message each other and share the board. Until then the other tools say what is missing.

Sessions are never listed, to anyone, and nobody types a session id. A session is in a pair only when its own person told it to join, and it is in at most one open pair.

## Tools

Every tool except the pairing ones works only inside the calling session's own connected pair. A session sees nothing of a pair it is not attached to.

## Delivery attempts recorded by tools

- `check_messages` records route `tool`, result `returned` for each message it returns to the recipient.
- `get_message` by the recipient records the same.
