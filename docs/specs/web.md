# Spec: web pages

Source: PLAN.md §6.9. Server-rendered (Eta) with HTMX and server-sent events. Every page except login, `/live` and `/ready` needs a login.

| Route                                             | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /login`                                      | Log in and sign up forms on one page. Sign-up asks for an invite code when `PAIR41_INVITE_CODE` is set                                                                                                                                                                                                                                                                                                                                                             |
| `POST /login`, `POST /signup`, `POST /logout`     | Wrong username or password: the page says so, HTTP 401                                                                                                                                                                                                                                                                                                                                                                                                             |
| `GET /connect`                                    | Connect your agent: the agent token (only right after sign-up or regenerate, shown bare so it can be pasted where the Claude Code plugin asks for it), a regenerate button, how to set up each agent (Claude Code: the Pair41 plugin from P41's plugin library, with the server to enter; Codex: `pair41 install --agents codex` from a clone; any other MCP agent: the URL and header; `/pair41:doctor` to check the plugin), and the conversation-sharing switch |
| `POST /connect/regenerate`                        | New token; the old one stops working                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `GET /pairs/:id`                                  | Pair room. Only the pair's two people; anyone else gets 404                                                                                                                                                                                                                                                                                                                                                                                                        |
| `GET /pairs/:id/live`                             | The live part of the room (HTMX partial), re-fetched when `/events` says something changed                                                                                                                                                                                                                                                                                                                                                                         |
| `POST /pairs/:id/messages`                        | A human posts into the thread (marked as from a human)                                                                                                                                                                                                                                                                                                                                                                                                             |
| `POST /pairs/:id/end`, `POST /pairs/:id/feedback` | End the pair; 👍/👎 with an optional note. The form says the note will appear on the analytics pages                                                                                                                                                                                                                                                                                                                                                               |
| `POST /settings/sharing`                          | Turn conversation sharing (prompts and agent replies) on or off                                                                                                                                                                                                                                                                                                                                                                                                    |
| `GET /events?pair=<id>`                           | Server-sent events: `changed` whenever something in that pair changes (pair members only)                                                                                                                                                                                                                                                                                                                                                                          |

## Pair room

- Header: feature, project, both people with agent, session state and activity; "Sharing your conversation with <partner>" with the switch.
- Open questions pinned at the top until answered; deferred ones stay pinned, marked deferred, with the reason.
- Timeline: each message with sender, kind, time, and only what the server observed: stored, each delivery attempt (route, time, result), acknowledged with ETA, answered, deferred.
- Feature board: items with kind, key, title, body, version, author, and a "changed" highlight for items updated in the last 10 minutes.
- Partner feed: both sides' feed lines (prompts and replies only from people sharing).
- Hint: "Your agent has N unread messages: tell it 'check pair'".
- A box to post into the thread, and "End pair" (in the header; see "End pair" below).

## Pairing between people (replaces the lobby of day two)

Pairs are between people; see "Pairing is between people" in mcp-tools.md. Agent sessions are never listed on any page.

| Route                     | What it does                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /lobby`              | Home. Your current pairs first (each with both people and whether each side's agent has joined), pair requests for you (accept or decline), then your teammates, with a live view of you and them. Until your agent has connected once, a card on top says to install the Pair41 plugin in Claude Code and points to Connect your agent for the token and other agents |
| `GET /people/:name`       | A teammate: online or when last seen, "Ask to pair" (a feature), and the history of every pair you two had, newest first, each linking to its room and conversation log                                                                                                                                                                                                |
| `POST /people/:name/pair` | Ask that person to pair (not yourself: there are no solo pairs)                                                                                                                                                                                                                                                                                                        |
| `POST /pairs/:id/respond` | Accept or decline                                                                                                                                                                                                                                                                                                                                                      |
| `GET /pairs/:id`          | Pair room: the pair code and the line to tell your agent ("join Pair41 pair <code>"), the two agents as a live view (messages travel between them), open questions, the thread, the board and the feed                                                                                                                                                                 |

A person is online when they were seen on the Pair41 page in the last 2 minutes or their agent was heard from in the last 5; otherwise the page says when they were last seen.

The thread and the conversation log are quiet rows: the time in a column on the left, then each event as a sentence from the viewer's side ("sam's Codex asked", "Your Claude answered", "You updated the contract PUT /items/:id to v2"), with a small dot in the side's colour by the name and the status in words ("answered in 14 s", "waiting for an answer"). An answer quotes the question it answers. Both list the newest first. A day divider starts each day, and "9 min earlier" marks a gap of two minutes or more. How a message was delivered is folded away under each message in the room.

**Look:** dark first (a light theme is one click away and remembered per browser). The live views are small particle simulations drawn from real data: on home, you in the middle and your teammates around you (online ones close and bright), with a bond to each person you are pairing with; in the pair room, the two agents, which pulse while working, with each message travelling between them as it arrives (questions, answers and board changes in their own colours). With reduced motion, the views are still.

## Added on day two (after the first real-agent run)

| Route                     | What it does                                                                                                                                                                                               |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /login?next=<path>`  | After logging in, go to `next` (a path on this site) instead of the lobby. Pages that need a login send you here with `next` set                                                                           |
| `GET /pairs/:id/log`      | Conversation log: one timeline of the whole pair, both sides. Messages, questions and answers, what each human asked their agent, what each agent concluded, commits and board changes, newest first, live |
| `GET /pairs/:id/log/live` | The live part of the log (HTMX partial)                                                                                                                                                                    |
| `GET /pairs/:id/log.md`   | The same log as markdown. Prompts and replies of someone who is not sharing are left out, as on the page                                                                                                   |

- **Pair open, agent not running:** a pair links two agent sessions and stays open when one of them stops (messages wait for it). The pair room says "agent working", "agent idle" or "agent not running" with when each was last heard from, and says "Pair open" (not "Live") unless both agents are running. When one side is not running, a notice says so; on your own side it gives the command that resumes that same session (`claude --resume <id>` or `codex resume <id>`), since a new session starts outside the pair. Codex has no session-end hook, so a stopped Codex counts as idle for up to 60 minutes.
- **Models:** when an agent's hooks report the model (`model` in the hook input), the session keeps it and the pair room shows it next to the agent, for example "Codex · gpt-6.2-sol".

## Redesign: status you can see at a glance

The pages follow the landing-page-design skill (`.claude/skills/landing-page-design`): Geist and Geist Mono, flat surfaces (deep navy from the Particle41 palette in the dark theme, as in the first Pair41 UI), the type scale and spacing tokens it lists, Phosphor icons inlined, one easing curve. The particle views stay and take the new palette; each has a pause button (remembered per browser), and they stay still with reduced motion. In the pair room's 3D view, a spark button under the pause button sends one message-like spark between the agents, from a random side; it is hidden while paused and in the 2D fallback. Every spark, real or from the button, takes a slightly different arc. A lightning button under it starts "catch the sparks": for 10 seconds sparks fly from both agents at a random pace, clicking one bursts it into particles, and a score in the top left counts hits and misses, then shows the final score for a few seconds. It is a toy: nothing is stored or sent.

**Needs you.** Every page, when logged in, shows a "Needs you" count in the top bar. It opens a list with a link (and, where it helps, a command to copy) for each thing:

| Kind        | When                                                                                                                                                                                              | Whose turn   |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| `request`   | Someone asked you to pair                                                                                                                                                                         | you          |
| `approval`  | A message from your agent waits for your approval (approve before send)                                                                                                                           | you          |
| `deferred`  | Your agent deferred a question from your partner's agent to you. Offers "Close"                                                                                                                   | you          |
| `join`      | The pair is agreed and your agent has not joined: the join line                                                                                                                                   | you          |
| `resume`    | Your agent in an open pair is not running: the resume command, when Pair41 knows the session id                                                                                                   | you          |
| `unread`    | Your agent has unread partner messages and no bridge pushes them: tell it "check pair"                                                                                                            | you          |
| `question`  | Your partner's agent asked yours a question that is still open                                                                                                                                    | your agent   |
| `accepted`  | Your partner accepted your pair request and you have not opened the room since (when your agent has not joined yet, this is folded into the `join` item: "sam accepted: tell your agent to join") | you          |
| `declined`  | Your partner declined your pair request, and you have not opened the room since                                                                                                                   | you          |
| `ended`     | Your partner (or their agent) ended the pair or withdrew their request, with their summary, and you have not opened the room since                                                                | you          |
| `nudge`     | Your partner nudged you, and you have not opened the room since                                                                                                                                   | you          |
| `same-file` | Both agents edited the same file in an open pair (the paths); stays until the pair ends                                                                                                           | your agent   |
| `overdue`   | A question from your agent has had no answer for 5 minutes, or the ETA your partner's agent gave has passed. Offers "Nudge"                                                                       | your partner |

`accepted`, `declined` and `ended` items are kept for 7 days. Opening the pair room (or its live part refreshing) marks everything in that pair as seen.

The count is the items that are your turn; your agent's and your partner's items are listed under them ("Your agent's turn", "Waiting on your partner"). `GET /needs` returns the list as an HTMX partial, polled every 10 s. Home shows the same list at the top when it is not empty.

**Browser notifications.** The Needs you panel has a switch to turn on browser notifications (remembered per browser; hidden when the browser has no Notification API). While any Pair41 tab is open, each new "your turn" item raises one notification, but only while the tab is hidden or not focused. Clicking it opens the item. Items already there when notifications are first turned on, or when the browser first loads the page, never raise one. Nothing arrives once every Pair41 tab is closed (no push service).

**Close a question.** `POST /pairs/:id/questions/:message/close` closes an open or deferred question in a pair you are in, from either side, for when the pair has moved past it. It is offered on `deferred` items in Needs you and on each question in the room's open questions. The question leaves the open lists, Needs you and the agents' open questions, shows `closed` in the thread, and the agent that asked it gets a system message (topic `closed`): "sam closed your question m_3 on the Pair41 page, so no answer is coming." That message does not wake the agent.

**Nudge.** `POST /pairs/:id/nudge` nudges your partner. It is offered (on their agent card in the room, and on `overdue` items) when the pair is agreed and either their agent has not joined for 5 minutes since the pair was accepted, their agent has not been heard from for 5 minutes or is not running, or a question to them is overdue. A nudge gives them a `nudge` item in Needs you (so a browser notification too) and, when their agent has joined, a short message from you in the thread, which the bridge pushes like any other. One nudge per person per pair every 5 minutes; the card says when the next one is possible.

**End pair.** The room header has a quiet "End pair" button (or "Withdraw request" when you asked and they have not answered) next to the tabs. It opens a small popover with the optional summary and a red confirm button. Whoever ends the pair is recorded (`ended_by`), so the other person gets the `ended` item.

**Pair room status.** The room opens with one status strip: the pair's state in words ("Live", "Pair open", "Waiting for sam to accept", "Ended"), both agents with their state, and the next step for you, coloured by whose turn it is: you (amber), waiting on your partner or the agents (neutral), all clear and live (green).

**Copy buttons.** Every command, code, token and join line has a copy button; the result is announced to screen readers.

**Login page.** Logged out, `/login` is the landing page: hero with the log in and sign-up card, the live view demo, how it works, a tagline, what you get, a short FAQ, and a final call to sign up. Facts on it come from this spec only.

**404.** Pages that do not exist, or pairs and people you cannot see, show a Pair41 "Not found" page with a way back.

## Space: the 3D layer

Built with the space-particle-scroll skill (`.claude/skills/space-particle-scroll`) on Three.js, GSAP ScrollTrigger and Lenis, served from our own `/static/vendor/<package>-<version>/` (versioned paths, cached for a year) through an import map. There is still no build step: the browser code is plain ES modules under `/static/space-<hash>/`. Static files are gzipped once at boot when the browser accepts it.

- **Agents.** On the landing page the two agents are neural clouds (particle neurons joined by filaments). In the live views an agent is drawn in one of two styles, chosen by `DEFAULT_STYLE` in `space/agents.js` (atom by default) and switchable per browser with `?agents=atom` or `?agents=orb` on any page. An atom: a packed particle nucleus, three tilted orbits of fine dots and an electron with a short trail on each (electrons race while working, drift while idle, stop when not running). An orb: a clean sphere of evenly spaced fine particles around a bright core. Working: the surface ripples and the core pulses. Idle: a slow turn and a gentle breath. Not running: grey and still. Not joined yet: an atom looks the same as not running; an orb is a faint grey outline inside a dashed ring. Your agent is Mint, your teammate's violet.
- **Landing (`/login`).** One fixed WebGL canvas behind the page. On wide screens the first screen shows the two agents on the left and the headline and log in card in a column on the right; on narrow screens they stack. The page opens mid-morph: particles still bursting outward as they settle into the two agents, joined by a particle bridge with messages flowing across it. Scrolling finishes the morph, moves the pair to the centre, and wraps them in a rotating text ring ("PAIR41 · ASK · ANSWER · AGREE"); the tagline lights up word by word near the top of the screen. A warp section of light streaks follows, then the content sections slide over the canvas. While the intro is on screen, the mouse pointer parts and lights the particles near it (not over the intro text, card or navs). A pill nav at the bottom tracks the section. The landing page is always dark.
- **Every logged-in page.** A little space behind the content: stars in three depth layers with scroll and mouse parallax, a faint drifting nebula, and a rare shooting star. Cards are slightly see-through with a blur so the space shows behind them; text keeps its contrast. In the light theme the nebula is off and the stars are fewer and darker.
- **Pair room, Home and a teammate's page.** The live views are drawn in 3D: the agents as particle orbs, the bond as a thin glowing beam with particles flowing along it, and each message as a pulse of light travelling along the beam. In the pair room the live view comes first, above the status strip. The views always have a dark background, in both themes. Labels are HTML.
- **Fallbacks.** No WebGL 2 or the scripts fail to load: the 2D canvas views (`sim.js`) run as before, and the landing hero shows its 2D demo. Reduced motion: no smooth scrolling, no warp, the hero shows the formed planets still, and the live views are drawn still. Rendering pauses while the tab is hidden or the canvas is off screen. Particle counts step down on small screens and few-core machines.
